# pipeline-anatomy (한국어)

[![CI](https://github.com/oh-namgyu/pipeline-anatomy/actions/workflows/ci.yml/badge.svg)](https://github.com/oh-namgyu/pipeline-anatomy/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

*(English: [README.md](README.md))*

1인이 실제로 운영 중인 콘텐츠 자동화 파이프라인 3종의 인터랙티브 케이스 스터디입니다.
각 레슨은 직접 조작하는 배관도입니다 — 입력을 고르고(어떤 출력 포맷인지, 렌더가
살아남는지, 품질 게이트가 통과시키는지) 그 실행을 다이어그램 위에서 한 단계씩
재생합니다. 스텝마다 해설이 붙고, 실패 분기는 각주가 아니라 실제 경로로 그려집니다.

레슨은 넷입니다. 세 파이프라인이 공유하는 뼈대 하나, 그리고 오디오북 라인 ·
멀티채널 콘텐츠 허브 · 스토리 설계→렌더 브리지가 각각 하나씩. 모든 레슨은 그
파이프라인이 왜 그 모양인지를 설명하는 설계 결정 카드로 끝납니다 — 왜 재고 큐인가,
왜 게이트를 렌더 앞에 두나, 왜 중단 산출물을 지우지 않나 — 그리고 3문항 퀴즈가
따라붙습니다.

정적 사이트입니다. 빌드 단계 없음, 서버 없음, API 키 없음, 계정 없음.

---

## ⚠️ 실제 프로덕션 시스템에서 일반화

**실제로 돌아가는 프로덕션 시스템에서 일반화했습니다(as-built 2026-08). 식별자·채널·
스케줄·수치는 전부 추상화되어 있으며, 2단 redact 게이트(사적 plaintext 스캔 +
salted-HMAC CI 검사)가 이를 강제합니다.**

구체적으로는 이런 뜻입니다. 여기서 설명하는 파이프라인은 실재하고 실제로 돌지만,
이 저장소의 어떤 것도 그것들을 지목하지 않습니다. 서비스명·채널·계정·호스트·경로·
포트·실행 시각·조회수·수익 수치, 전부 없습니다. 실제 시스템에 고유명사가 있는
자리에 레슨은 역할을 둡니다 — "발행 플랫폼", "공개 아카이브", "스케줄러". 넘어오는
것은 아키텍처와 실패 양상과 그 이유이고, 어차피 읽을 가치가 있는 부분도 그쪽입니다.

이것은 **형태**에 대한 케이스 스터디이지 **수치**를 늘어놓는 포트폴리오가 아닙니다.

## 레슨

| # | 레슨 | 분 | 무엇을 조작하나 |
| :-- | :--- | :-- | :--- |
| L0 | 공통 기반 구조 | 5 | 품질 게이트(통과 / 거부) × 큐(재고 있음 / 비어 있음) |
| L1 | 오디오북 라인 | 7 | 출력 포맷(롱폼 / 쇼츠 / 중폼) × 렌더(완주 / 중간 사망) |
| L2 | 멀티채널 콘텐츠 허브 | 6 | 소스 어댑터(수확한 아카이브 / 큐레이션 시드) × 게이트(통과 / 리스크 차단) |
| L3 | 스토리 설계→렌더 브리지 | 7 | 캐스팅(도감에 있음 / 새 배우) × 검수(승인 / 반려) |

입력 조합 하나하나에 각자의 시나리오가 쓰여 있습니다 — 스키마 게이트가 이를
강제하므로, UI 에서 고를 수는 있는데 아무도 쓰지 않은 분기는 프로덕션의 놀람이 아니라
테스트 실패가 됩니다. 진행도는 `localStorage` 에 저장되며 브라우저를 벗어나지 않습니다.

L0 이 맨 앞인 데는 이유가 있습니다. 세 파이프라인은 서로 몇 년 간격으로, 서로 무관한
목적으로 만들어졌는데도 같은 뼈대로 수렴했습니다 — 예약 실행이 큐에서 한 건을
클레임하고, 무언가를 생산하고, 게이트를 통과시키고, 렌더하고, 발행 큐에 넣고, 실행을
보고합니다. L0 을 먼저 읽으면 나머지 세 레슨이 **어디서 갈라지는지**에 대한 공부가
됩니다.

## redact 게이트의 동작

일반화는 주장이므로 테스트합니다. 서로 독립적인 2단입니다.

**1선 — 사적, plaintext, 이 저장소에 없음.** 결정적 스크립트가 체크아웃을 치환표(모든
실명을 공개 역할명으로 대응시킨 표)와 대조합니다. 유니코드 NFC 정규화와 제로폭 문자
제거를 거친 뒤 대소문자를 무시하고 부분 문자열로 매칭하며, 파일 내용과 파일명을 모두
훑습니다. 공개하지 않는 이유는 단순합니다 — 감추려는 이름의 목록을 공개하는 것은 그
이름을 다시 노출하는 일입니다. 공개 직전마다 실행되며, 위반 픽스처를 심고 검출을
단언하는 자가 테스트를 자체적으로 가지고 있습니다.

**2선 — 공개, CI, 이 저장소 안.** `tests/redact.test.mjs` 가 매 푸시마다 두 갈래로
돕니다.

- *형태 규칙*은 비밀이 필요 없어 포크를 포함해 어디서나 돕니다. 파일시스템 경로,
  포트 번호, 계정 핸들, 벽시계 시각, 절대 URL — 일반화된 모델이 담고 있을 이유가 없는
  것들이므로 하나하나가 위반입니다. URL 허용목록은 짧고 명시적이며 주석이 달려
  있습니다(표준 엔드포인트, 로컬 dev 서버, 그리고 이 프로젝트 자신의 공개 주소).
- *salted-HMAC 대조 목록*은 나중에 실명이 다시 들어오는 것을 잡습니다.
  `tests/redact-hmac.json` 은 사적 표의 모든 항목에 대한 `HMAC-SHA256(salt, 항목)` 을
  담습니다. 엔트로피가 낮은 이름은 평범한 해시로 공개하면 사전 공격에 수 초 만에
  무너지므로, 이 파일을 커밋해도 안전하게 만드는 것은 salt(`REDACT_SALT`, CI
  시크릿)입니다 — salt 가 없으면 이 파일은 어떤 특정 이름에 대해서도 아무것도
  증명하지 않고, salt 가 있으면 CI 는 실명을 되살린 커밋을 여전히 거부할 수 있습니다.
  salt 가 없을 때 이 갈래는 조용히 통과하는 대신 **소리 내어 skip** 합니다. 포크는
  거짓 안심 대신 분명한 안내를 받고, 형태 규칙은 그대로 전부 돕니다.

CI 에서는 이 게이트가 별도 `redact` 잡으로 따로 보입니다. 실패했을 때 "어떤 테스트가
깨졌다"가 아니라 "redact 이 걸렸다"로 읽히게 하기 위해서입니다.

**알려진 한계, 솔직하게.** 두 선 모두 텍스트를 봅니다. 이미지 안에 구워진 글자는 양쪽
모두에게 보이지 않고, 아무도 등록하지 않은 표기(호모글리프, 특이한 음차, 3어절 변형)도
마찬가지입니다. 그것들은 1선과 사람의 최종 리뷰가 담당합니다. 이미지 쪽은 탐지가 아니라
구조로 막습니다 — **커밋되는 모든 스크린샷은 `scripts/shots.mjs` 에서 나와야 하며**, 이
스크립트는 커밋된 레슨 데이터만 렌더하므로 그릴 수 있는 모든 것이 이미 소스 단계에서
스캔을 통과한 것입니다. 수동 캡처 이미지는 그때 화면에 있던 다른 무엇이든 함께
담기는데, 그 구멍이 정확히 문제입니다.

## 실행

**라이브 데모:** https://pipeline-anatomy.vercel.app

**로컬** — 클론한 뒤 정적 파일을 서빙하는 아무 서버로나 띄웁니다.

```bash
git clone https://github.com/oh-namgyu/pipeline-anatomy.git
cd pipeline-anatomy

python3 -m http.server 6185     # 출력되는 주소를 브라우저에서 엽니다
# 또는
npx serve .
```

`index.html` 을 파일시스템에서 직접 여는 것은 **동작하지 않습니다**. 이 앱은 ES
모듈이고, 브라우저는 `file://` 에서 모듈 로드를 거부합니다. 정적 서버라면 무엇이든
됩니다.

## 개발

```bash
npm ci                                  # dev 의존성: @playwright/test 하나뿐
npm test                                # node --test — 스키마 게이트·레슨 데이터·redact
npx playwright install chromium         # 최초 1회
npx playwright test                     # python3 정적 서버 위에서 e2e
node scripts/shots.mjs                  # 위 스크린샷 재생성
```

런타임 의존성은 없습니다. 페이지는 외부 호스트에서 아무것도 불러오지 않습니다 — CDN
스크립트도, 웹폰트도, 애널리틱스도. `default-src 'self'` CSP 메타 태그와 `vercel.json`
의 동일한 CSP 응답 헤더가 이를 강제합니다.

**레슨은 데이터 모듈입니다.** `js/lessons/*.js` 는 평범한 객체를 export 하고, 엔진
(`js/engine/`)은 스키마를 통과하는 객체라면 무엇이든 렌더합니다. 레슨 추가는 파일 하나와
`js/lessons/index.js` 한 줄이며 엔진은 건드리지 않습니다. 스키마 형태·검증기 에러 코드·
새 콘텐츠가 redact 2선을 모두 통과해야 한다는 규칙은
[CONTRIBUTING.md](CONTRIBUTING.md) 에 있습니다.

레슨 엔진은 [**cc-anatomy**](https://github.com/oh-namgyu/cc-anatomy) 에서 이식했습니다.
같은 기계 장치를 다른 주제에 쓰는 형제 프로젝트입니다(MIT, 동일 저자). 이식된 파일은
각각 원본 커밋 해시를 헤더에 기록해 두어, 한쪽의 수정을 다른 쪽에서 추적할 수 있습니다.

## 로드맵

- **L4 — 오케스트레이터**: 이 셋의 위층. 하나의 스케줄러가 독립된 파이프라인들로
  팬아웃하고, 공유 렌더 기계를 두고 중재하며, 한 갈래만 실패했을 때 "실행이 실패했다"가
  무슨 뜻인지 정해야 하는 층입니다.
- **엔진 공용 패키지화**: 다이어그램·플레이어·위젯·스키마 모듈이 현재 이 프로젝트와
  형제 프로젝트에 중복되어 있습니다. 하나의 패키지로 추출하는 것이 해법이고, 그때까지의
  완화책이 이식 파일마다 박아 둔 원본 커밋 헤더입니다.
- **스크린리더 대응**: 현재의 키보드·`prefers-reduced-motion` 지원을 넘어, 스텝 변화를
  읽어 주는 live region.
